# 公開サイトの保護と運用

[READMEに戻る](../README.md)

## いいねAPI

`/api/blog-like` は公開済みの記事slugだけを受け付けます。POSTは本番のOriginを確認し、本文を最大2KiBに制限します。Origin確認はブラウザからの別サイト経由の操作を防ぐもので、直接リクエストの認証ではありません。

Firestoreの `blog-like-private/budget-read` と `budget-write` の固定文書をトランザクションで更新し、全インスタンス共通の上限を適用します。UTCの分・日単位でリセットします。

- 書き込み：全体で30回/分、500回/日。
- 集計：全体で60回/分、3,000回/日。結果はワーカー内で60秒キャッシュします。

上限到達時は429、DB障害時は503を返し、書き込みは行いません。上限は全訪問者共通なので、攻撃で上限に達した場合は通常の操作も一時停止します。上限を変更する場合は `src/security/likeBudget.ts` を確認してください。これで関数の起動回数・拒否判定のDB読み取り費用までゼロにはできません。必要に応じてホスティング側でもリクエスト制限を設定します。

集計は公開記事ごとのFirestore集計クエリで行い、全いいね文書をダウンロードしません。新規文書IDは記事とクライアント識別情報のハッシュで決まり、同時操作はトランザクションで処理します。新規文書にはIPを平文で保存しません。既存のいいねは保持し、本人の次回取り消し時に旧文書を削除します。IPによる識別は厳密な本人確認ではなく、共有回線・変更されたIP・転送ヘッダーに影響されます。全体の上限はIPに依存しません。

既存のFirestore deny-allルールを維持します。追加の複合インデックスは不要です。

## リモートMCP

`/api/labs/mcp-tools` と配下の天気・時計APIは削除しています。旧URLは404となり、OpenWeatherへの呼び出しもありません。`OPENWEATHER_API_KEY` はこのアプリでは使用しません。

## 下書きと外部スクリプト

Notesの下書きはlocalStorageでの自動保存を維持します。同じオリジンのJavaScriptはこの保存内容を読めるため、サイト全体から広告・Google Analytics・X埋め込み用の外部JavaScriptを外しています。Xのプロフィールと記事中の投稿は外部リンクで開きます。

CSPで実行するスクリプトの取得元を `self` に限定しています。Next.jsのインライン初期化は許可し、開発時のみevalも許可します。これはXSS全般や悪意ある同一オリジンのコードから下書きを隔離する仕組みではありません。外部スクリプトを再導入する場合は、下書き保存を独立オリジンへ移すなど、先に保存領域の境界を見直してください。

## 検証

`tests/site-security.test.cjs` で不正入力・未知の記事・Origin・保存/取り消し・旧いいね・集計キャッシュ・分/日上限・MCP処理の削除を検証します。Firestoreはモックを使用し、本番データへ書き込みません。実際の分散トランザクションとホスティング側のIPヘッダー処理はモック検証の範囲外です。
